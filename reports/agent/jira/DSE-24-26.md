## 2. Objective & Acceptance Criteria
DSE-24: rubric scoring, teacher per-criterion scores, total = weighted sum, `POST /api/submissions/:id/grade`. DSE-26: `POST /api/submissions/:id/finalize` → status graded, lock (admin override), notify student, gradedAt/gradedBy, grade history.

## 3. Initial Survey
No grading API existed. The run worker set `status` to `graded`/`failed` (not in enum) and overwrote `feedback` after every sandbox run, locking submissions before any teacher grading.

## 4. Execution Log
- 2026-11-23: `grading.service.ts` with `listForReview`, `getSubmissionDetail`, `gradeSubmission`, `finalizeSubmission`, `computeRubricScore`, `toStudentView(s)`. Model: `runStatus`, `runMessage`, `lastRunAt`, `criterionScores` (snapshot), `aiReview`, `gradeHistory`. Worker writes run fields only. Student responses (list, detail, run-result) never include AI review/history/draft grade/hidden test output; run-result returns only the sandbox summary.
- Decision: score formula `round(Σ(score/max × weight)/Σweight × assignment.maxScore)`; no rubric → plain score ≤ maxScore.
- Out of scope (demo): automatic mapping of test-case points to rubric criteria (DSE-24 AC 2) — teachers see the auto test score and type criterion scores.
